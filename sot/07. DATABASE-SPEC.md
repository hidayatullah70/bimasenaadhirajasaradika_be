# 17. DATA INTEGRITY RULES

Database wajib menjaga:

### Unique

```text
users.email
employees.employee_no
clients.client_code
sites.site_code
services.code
invoices.invoice_no
```

### Referential Integrity

Foreign key tidak boleh menunjuk ke record yang tidak tersedia.

### Historical Data

Data yang memiliki histori operasional tidak boleh sembarangan dihapus.

Gunakan:

```text
status
```

atau:

```text
is_active
```

untuk deactivation.

---

# 18. DELETE STRATEGY

Recommended:

```text
users        → soft deactivate
employees    → soft deactivate
clients      → soft deactivate
sites        → soft deactivate
services     → deactivate
placements   → status
attendance   → retain
invoices     → retain
activities   → retain
```

Hard delete hanya diperbolehkan apabila tidak menyebabkan kehilangan histori atau melanggar referential integrity.
